# Optional features list to propose to Klas

- **Date:** 2026-10-12 (Monday meeting, held over text chat)
- **Status:** Accepted
- **Related issues:** none yet

## Situation

At the 2026-10-08 meeting, Fadi proposed preparing a list of optional
features (beyond the MVP) to present to Klas at the next meeting with him.

## Decision

Propose the following list to Klas. Nothing on it is committed work; Klas
and the group decide later what, if anything, gets built.

From the project plan's delimitations (out of scope for the MVP):
- Built-in payment or course booking.
- Practical elements (shooting test, search test).
- A full native mobile app (App Store / Google Play) instead of the PWA.

Question bank and course management:
- Archive questions instead of only deleting them, so the active question
  pool can be a subset of all questions.
- Group students by course or year.
- Question change history (who changed which question, and when).
- Export learner progress (e.g. CSV).
- Course announcements shown on the learners' dashboard.

For learners:
- Weak-area practice: more questions from the subjects where the learner
  scores lowest.
- An explanation after each answer, with a law/regulation reference where
  relevant.
- Species identification mode (image quiz).
- Exam readiness indicator (e.g. "passed 4 of your last 5 mock exams").
- Report a question (error or unclear wording), shown in the admin area.

General:
- Swedish/English language toggle.
- Accessibility pass (keyboard navigation, contrast, screen readers).

## Alternatives considered

None; the list collects the group's ideas for Klas to prioritise.

## Consequences

Hans brings the list to the next meeting with Klas. Features he wants go on
the board as issues; the rest stay as ideas.
