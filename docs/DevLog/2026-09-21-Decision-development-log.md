# Create a development log file

- **Date:** 2026-09-21
- **Status:** Accepted
- **Related issues:** #41

## Situation

The project plan states: "Document the system (requirement specification, system sketch, test results and commissioning guide) so that it can be managed further after the internship period," and describes a weekly rhythm of Monday planning, daily reconciliation, Friday demos with an updated task board, and pull requests reviewed by a colleague. This implies keeping track of progress, which the previous group did not do.

## Decision

Start a development log. Hans takes responsibility for setting it up.

## Alternatives considered

None recorded.

## Consequences

- The log needs a place to live in the repo (`docs/DevLog/`) and a format simple enough for a group of this size to keep up with two to three entries a week.
- Keeping it current is a shared responsibility: whoever makes a decision or runs a meeting writes the entry.
- It sits alongside the GitHub Issues and Project board rather than replacing them: issues track what work is left, the log records why a choice was made.
